= Solace Spark Connector Source Configuration Options
:doctype: book

[cols="2m,1m,1m,1m,2", options="header"]
|===
| Config Option
| Type
| Valid Values
| Default Value
| Description

| host
| string
| any
|
| Fully Qualified Solace Hostname with protocol and port number.

| vpn
| string
| any
|
| Solace VPN name.

| username
| string
| any
|
| Solace Client Username.

| password
| string
| any
|
| Solace Client Password.

| connectRetries
| int
| (-1) or greater
| 0
| Number of times to retry connection during initial setup. 0 means no retries. -1 means retry forever.

| reconnectRetries[[reconnect-retries]]
| int
| (-1) or greater
| 3
| Number of times to attempt reconnection after a disconnect. 0 means no retries. -1 means retry forever.

| connectRetriesPerHost
| int
| (-1) or greater
| 0
| When using a host list, defines how many times to try connecting to a single host before moving to the next. 0 means one attempt. -1 means infinite retries on the first host only.

| reconnectRetryWaitInMillis
| int
| 0 - 60000
| 3000
| Time in milliseconds to wait between each connection or reconnection attempt.

| connectIdleTimeoutInMillis[[connect-idle-timeout-in-millis]]
| int
| Timeout in Milliseconds
| 0
| Time in milliseconds before closing an idle connection to Solace. Useful in long-running clusters where Spark sessions do not terminate gracefully.

| connectIdleTimeoutCheckInMillis[[connect-idle-timeout-check-in-millis]]
| int
| Timeout in Milliseconds
| 0
| Interval in milliseconds at which to check for idle connections. Connections idle beyond the configured timeout are closed automatically.

| solace.apiProperties.<Property>
| any
| any
|
a| Additional Solace Java API properties can be set using `solace.apiProperties.<Property>` where `<Property>` is defined in the https://docs.solace.com/API-Developer-Online-Ref-Documentation/java/constant-values.html#com.solacesystems.jcsmp.JCSMPProperties[Solace Java API documentation].

Example:
[source,yaml]
----
solace.apiProperties.reapply_subscriptions=false
solace.apiProperties.client_channel_properties.keepAliveIntervalInMillis=3000
----

| solace.oauth.client.access-token
| string
| absolute file path
| empty
| Absolute path to a file containing a rotating access token. The connector reads the token directly from the file. Requires <<solace-oAuth-client-refresh-interval, solace.oauth.client.token.refresh.interval>> to be configured.

| solace.oauth.client.auth-server-url
| string
| any
| empty
| Full URL of the token endpoint used to fetch the access token.

| solace.oauth.client.client-id
| string
| any
| empty
| OAuth Client ID.

| solace.oauth.client.credentials.client-secret
| string
| any
| empty
| OAuth Client Secret.

| solace.oauth.client.auth-server.client-certificate.file
| string
| any
| empty
| Absolute path to the X.509 client certificate file for TLS connections.

| solace.oauth.client.auth-server.truststore.file
| string
| any
| empty
a| Absolute path to the trust store file for TLS connections.

* If a JKS file is available, provide the absolute path to load it directly.
* If `solace.oauth.client.auth-server.client-certificate.file` is configured, provide a path including the file name. The connector will load the client certificate into a keystore and save it as a JKS file.

| solace.oauth.client.auth-server.truststore.password
| string
| any
| empty
a| Password for the JKS trust store file.

* If a JKS file is available, provide its password.
* If `solace.oauth.client.auth-server.client-certificate.file` is configured, provide a password to protect the generated JKS file.

| solace.oauth.client.auth-server.ssl.validate-certificate
| boolean
| true or false
| true
| Enables or disables SSL certificate validation. If set to `false`, TLS requests are sent without validation.

| solace.oauth.client.auth-server.tls.version
| string
| SSL, TLS, TLSv1, TLSv1.1, TLSv1.2, TLSv1.3
| TLSv1.2
| TLS protocol version for the SSL connection.

| solace.oauth.client.token.refresh.interval[[solace-oAuth-client-refresh-interval]]
| int
| positive integer
| 60
| Interval in seconds at which the connector fetches a new access token. Configure this value to be less than your token expiry time to avoid disconnections.

| solace.oauth.client.token.fetch.timeout
| int
| positive integer
| 100
| Connection timeout in milliseconds for access token requests.

| queue
| string
| any
|
| Solace Queue name.

| queue.receiveWaitTimeout
| int
| Timeout in milliseconds
| 10000
| Maximum time to wait before submitting available messages to a Spark micro-batch.

| queueFullCheckWaitTimeoutInMillis
| int
| positive integer
| 1000
| Maximum time to wait, per attempt, when checking whether the queue has messages available before starting a micro-batch.

| queueFullCheckRetries
| int
| positive integer
| 5
| Number of polling attempts, each bounded by `queueFullCheckWaitTimeoutInMillis`, before concluding the queue is empty and skipping the micro-batch.

| reuseBrowserConnections
| boolean
| true or false
| true
a| Controls whether the Browser connections used to check LVQ checkpoints and queue depth are held open and reused across micro-batches, or recreated on every check.

* `true` — the two Browser flows are provisioned once and reused for the life of the query. Fewer broker-side flow provision/teardown round-trips, at the cost of 2 standing egress flows per query.
* `false` — a new Browser is provisioned and torn down on every check. No standing flows between micro-batches, at the cost of additional broker-side provisioning overhead per micro-batch.

Set to `false` if running many concurrent queries against a broker with a constrained egress flow limit (see your Solace service's client profile / service class limits).

| batchSize
| int
| any
| 1
| Number of messages to process per batch. For optimal throughput, configure the Solace queue's Maximum Delivered Unacknowledged Messages per Flow to twice the batch size.

| replayStrategy
| string
| BEGINNING \| TIMEBASED \| REPLICATION-GROUP-MESSAGE-ID
| empty
| Replay strategy for replaying messages from the broker. See https://docs.solace.com/Features/Replay/Msg-Replay-Concepts-Config.htm#Types[Solace Replay Configuration].

| replayReplicationGroupMessageId
| string
| valid replication group message id
| empty
| Required when `replayStrategy` is `REPLICATION-GROUP-MESSAGE-ID`. Message playback starts after this replication group message ID.

| replayStartTime
| string
| yyyy-MM-dd'T'HH:mm:ss
| empty
| Required when `replayStrategy` is `TIMEBASED`. Messages equal to or newer than this date and time are replayed. Cannot be earlier than the replay log creation date.

| replayStartTimeTimezone
| string
| valid timezone
| UTC
| Timezone for `replayStartTime`. Required when `replayStrategy` is `TIMEBASED`.

| ackLastProcessedMessages
| boolean
| true or false
| false
a| When set to `true`, the connector identifies and acknowledges messages processed in the last run during restart. Depends on the Spark checkpoint.

NOTE: Enable only when the downstream system has successfully processed data in the previous run. This property has no effect when a replay strategy is configured.

| includeHeaders
| boolean
| true or false
| false
| When set to `true`, message headers are included in the output.

| partitions
| int
| any
| 1
| Number of consumers for the configured queue. Consumers are distributed across worker nodes. Set to `0` to create one consumer per worker node, scaling automatically as nodes are added.

| lvq.name
| string
| valid lvq name
| empty
| Name of the LVQ configured on the Solace broker. Used to communicate checkpoint information from worker nodes to the driver node and ensures checkpoint data is present in both the LVQ and Spark checkpoint directory.

| lvq.topic
| string
| valid solace topic
| empty
| Topic subscribed by the LVQ on the Solace broker. Each worker node publishes checkpoint information to this topic.

| lvqPublishRetries
| int
| 0 or greater
| 3
| Number of retry attempts when publishing checkpoint data to the LVQ fails due to a transient connection issue (for example, a broker-side disconnect). 0 means no retries; the connector fails the query immediately on the first failure.

| lvqPublishRetryIntervalInMillis
| int
| positive integer
| 1000
| Initial wait time in milliseconds before retrying a failed LVQ checkpoint publish. Doubles after each subsequent retry (exponential backoff).

| ignoreCheckpointMessageIdComparisonError
| boolean
| true or false
| false
a| Specifies whether to ignore errors when comparing an incoming message's Replication Group Message ID against the checkpointed message ID during restart.

* `false` — throws `SolaceReplicationGroupMessageIdNotComparableException` and stops processing.
* `true` — logs a warning, skips the comparison, and continues. The message is treated as new and will not be deduplicated.

NOTE: This error typically occurs when messages originate from different replication groups.

| sparkRuntimePlatform[[spark-runtime-platform]]
| string
| DATABRICKS, OTHER
| DATABRICKS
a| Runtime platform on which the Spark application is deployed. Required when a Databricks Unity Catalog Volume is used as the checkpoint location.

* `DATABRICKS` — enables Unity Catalog Volume support for checkpointing.
* `OTHER` — disables the Unity Catalog Volume check.

| databricksSecretScope[[databricks-secret-scope]]
| string
| valid secret scope name
| empty
| Databricks secret scope used to retrieve authentication credentials for accessing Unity Catalog Volumes as the checkpoint location.

| databricksHost[[databricks-host]]
| string
| valid secret name
| empty
a| Secret name within the configured secret scope that holds the Databricks workspace host URL. Required when `spark_runtime_platform` is `DATABRICKS` and the checkpoint path contains `Volumes`.

Refer to https://learn.microsoft.com/en-us/azure/databricks/dev-tools/auth/oauth-m2m#step-2-use-oauth-authorization[Databricks OAuth Workspace level Environment Variables] for valid host value

| databricksClientId[[databricks-client-id]]
| string
| valid secret name
| empty
a| Secret name within the configured secret scope that holds the Databricks service principal client ID. Required when `spark_runtime_platform` is `DATABRICKS` and the checkpoint path contains `Volumes`.

For relevant value refer to https://learn.microsoft.com/en-us/azure/databricks/dev-tools/auth/oauth-m2m#step-2-use-oauth-authorization[Databricks OAuth Workspace level Environment Variables] for valid client id value

NOTE: Ensure the service principal has access to the configured Unity Catalog Volume checkpoint path and Databricks secret scope.

| databricksClientSecret[[databricks-client-secret]]
| string
| valid secret name
| empty
a| Secret name within the configured secret scope that holds the Databricks service principal client secret. Required when `spark_runtime_platform` is `DATABRICKS` and the checkpoint path is `Unity Catalog Volume`.

For relevant values refer to https://learn.microsoft.com/en-us/azure/databricks/dev-tools/auth/oauth-m2m#step-2-use-oauth-authorization[Databricks OAuth Workspace level Environment Variables] for valid client secret value

See <<databricks-client-secret-notes>>.

| databricksClientSecretRefreshInterval[[databricks-client-secret-refresh-interval]]
| long
| positive integer (minutes)
| 1440
a| Interval in minutes at which the connector fetches the latest client secret from the configured Databricks secret scope.

The user is responsible for ensuring:

* Rotation completes before the next refresh interval triggers.
* Both rotation and refresh complete before the existing secret expires.

WARNING: If the refresh interval triggers before rotation is complete, the connector fetches the old secret and continues using it until the next refresh cycle.

|===

[[databricks-client-secret-notes]]
Databricks Client Secret — Important Notes

NOTE: Always manage this credential using Databricks secret scopes. Never expose it in plain text.

IMPORTANT: Secret rotation is not managed by the connector. The platform administrator is responsible for rotating the secret and updating it in the secret scope. The connector fetches the updated secret automatically based on the interval configured in `databricks_client_secret_refresh_interval`. No restart is required.
